# LinkUp 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build LinkUp 1.0 as a real Android/iOS messaging product with a production backend, PostgreSQL persistence, realtime messaging, offline sync, secure authentication, original UX, notifications, moderation, observability, and safe releases.

**Architecture:** React Native + Expo + TypeScript mobile client communicates with a NestJS + TypeScript modular monolith over versioned REST and WebSockets. Neon PostgreSQL is the authoritative source of truth; Railway hosts the backend; GitHub owns source/versioning/CI; media uses an object-storage abstraction and push uses Expo Notifications/APNs/FCM.

**Tech Stack:** React Native, Expo, TypeScript, NestJS, REST `/api/v1`, WebSockets, Neon PostgreSQL, Railway, GitHub, Expo Notifications/APNs/FCM, object-storage abstraction, PostHog/infrastructure monitoring.

**Spec:** `docs/design/linkup-v1.md`

## Global Constraints

- Build Android and iOS from one React Native + Expo + TypeScript codebase.
- Backend is a NestJS + TypeScript modular monolith; do not begin with microservices.
- Neon PostgreSQL is the authoritative persistent source of truth.
- REST is versioned under `/api/v1`; WebSockets handle live events.
- V1 is secure server-side messaging and is explicitly NOT true end-to-end encryption; never claim E2EE.
- Support 1:1 messaging with text, images, short videos, voice messages, and files/documents.
- Use client-generated idempotency IDs and authoritative server message IDs.
- Preserve accounts, conversations, settings, and data across updates and migrations.
- Email is private and must never be exposed through public search.
- `@username` is globally unique and case-insensitive; display names are non-unique.
- Use original LinkUp visual identity and custom iconography; do not copy another app pixel-for-pixel or present generic existing icon glyphs as the brand/UI identity.
- Use TLS, strict authorization, membership checks, rate limits, abuse controls, secure sessions, secure media access, and security event logging.
- GameVisionAndroid is unrelated and must never be modified.
- No placeholder or fake backend behavior in production paths.

## Repository Structure

Create a workspace with focused boundaries:

- `apps/mobile` — Expo React Native application, navigation, UI, local persistence, sync, notifications.
- `apps/api` — NestJS modular backend, REST controllers, WebSocket gateway, services, guards.
- `packages/contracts` — shared TypeScript DTO/event schemas and error contracts.
- `packages/config` — shared validated configuration primitives.
- `packages/design-system` — mobile theme tokens and original LinkUp components/icons where practical.
- `packages/eslint-config` and `packages/tsconfig` — shared engineering configuration.
- `database/migrations` — versioned PostgreSQL migrations.
- `docs/design` — approved product/architecture specification.
- `docs/superpowers/plans` — implementation plans.
- `.github/workflows` — CI, test, and release automation.
